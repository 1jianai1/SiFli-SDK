# AIC8800D80 网络连通性测试手册（`nettest` 命令 + 手机热点排查流程）

> **适用工程**：`example/aic8800_d80`
> **适用对象**：不熟悉网络排查的使用者。本文所有命令都是**直接抄进串口 `msh />` 回车**即可。
> **相关文档**：故障根因见 [aic8800d80_netdev_linkup_and_ping_fix.md](aic8800d80_netdev_linkup_and_ping_fix.md)。

## 0. 为什么需要 `nettest`

固件里原本能用的网络工具只有两个：

| 工具 | 协议 | 局限 |
|---|---|---|
| `ping`（netdev 版） | ICMP | **只能测 ICMP**。很多热点/企业网只封 ICMP，于是板子明明能上网也 ping 不通 |
| `iperf` | TCP/UDP | 需要一个对端跑 iperf 服务端，手边没有服务器就用不了 |

所以出现"能 ping 通网关、能解析域名，但 ping 不通任何公网地址"时，**无法判断**到底是：

- (a) 公网 TCP 也通，只是 **ICMP 被网络策略丢弃** → 设备与协议栈完全没问题；
- (b) 公网 TCP 也不通 → 出口/热点共享被限制。

`nettest` 就是这两者的判据：做一次 TCP 连接（三次握手），用**有没有回应**来回答"网络到不到得了外面的世界"。

---

## 1. 命令一览

```sh
ifconfig                                # 看接口状态/IP/网关/DNS
ping <ip或域名>                          # ICMP 测试(可能被网络策略丢弃)
nettest <ip或域名> <端口> [超时秒数]       # ★ TCP 连接测试(本手册主角)
iperf -s                                # 板子当 iperf 服务端
iperf -c <ip>                           # 板子当 iperf 客户端(需要对端先跑 iperf -s)
```

## 2. `nettest` 用法

```
nettest <ip或域名> <端口> [超时秒数, 默认 8]
```

端口填对方**确实在监听**的端口。常用组合：

```sh
nettest 180.101.51.73 80        # 直接给 IP (就是 ping www.baidu.com 解析出的那个)
nettest www.baidu.com 80        # 也可以给域名, 内部会先做一次 DNS 解析
nettest 114.114.114.114 53      # 114 的 DNS 端口(TCP 53)
```

三种打印结果的判读（**注意看耗时那一栏，它是关键**）：

| 打印 | 含义 | 说明 |
|---|---|---|
| `CONNECT OK` | 三次握手成功 | **公网 TCP 是通的**。ICMP 不通只是被策略丢弃 |
| `CONNECT FAIL (errno=…, **0 ms**)` | **本地就失败了，一个包都没发出去** | 这是**驱动/协议栈问题**，不是网络问题。典型是 `errno=118`（`EHOSTUNREACH`，本地路由查表失败）→ 见 [补丁4](aic8800d80_lwip_netif_default_missing.md) |
| `CONNECT FAIL (errno=111/104, 几 ms~几百 ms)` | 对端回了 RST / 重置 | 包走到了对方。**网络是通的** |
| `TIMEOUT`（约等于你设的超时值，如 8000 ms） | 无任何回应 | 数据被网络丢弃。**这才是"网络真的不通"** |

> **判读要点**：只看 `CONNECT OK` / `FAIL` / `TIMEOUT` 这几个字**不够**。
> 真正的分界线是"**多久失败的**"：
> - 耗时 **0 ms** → 本地问题（驱动/路由表），和网络无关；
> - 耗时 **几毫秒到几百毫秒** → 收到了对方的回应，网络通；
> - 耗时 **接近超时上限** → 无人应答，网络不通。

## 3. 手机热点场景的完整排查流程

板子连的是**手机热点**时，能做的对照很有限（没有同网段的第二台 PC）。按下面顺序走，每一步都能独立得出结论。

### 第 1 步：先在手机上确认（不用敲命令）

| 检查项 | 怎么做 | 为什么要查 |
|---|---|---|
| 手机自己能不能上网 | 关掉手机 Wi-Fi，只用移动数据，打开浏览器/微信 | 手机没网，热点自然也没网 |
| 移动数据是否打开 | 设置 → 移动网络 | 最常见的原因 |
| 套餐是否允许"个人热点/网络共享" | 设置 → 个人热点，看有无运营商提示 | **部分运营商/套餐禁止共享**，现象就是：客户端能连上、能拿到 IP、甚至能解析域名，但数据全部收不到 |
| 已连接设备列表 | 热点设置里看有没有本机 MAC `cc:c4:b2:dc:17:ed` | 确认板子确实连到了这台手机的热点上 |

### 第 2 步：板子上逐条敲

连上热点、`dhcp finish` 之后：

```sh
ifconfig
ping 10.237.107.49
nettest 180.101.51.73 80
nettest 114.114.114.114 53
nettest www.baidu.com 80
```

> 第 2 条里的 IP 请换成 `ifconfig` 里 `gw address:` 显示的那个值（当前实测是 `10.237.107.49`）。
> 第 3/4/5 条的 IP 可以照抄，它们是公网地址。

### 第 3 步：看结果下结论

| `ifconfig` | `ping 网关` | `nettest` | 结论 | 下一步 |
|---|---|---|---|---|
| `UP LINK_UP` + 有 IP | 通 | `CONNECT OK` | **设备完全正常**，只是网络封 ICMP | 直接去跑业务（MQTT/HTTP），别再纠结 ping |
| `UP LINK_UP` + 有 IP | 通 | `TIMEOUT`（全部） | 热点/运营商**没有把共享流量放出去** | 第 4 步 |
| `UP LINK_UP` + 有 IP | 通 | `CONNECT FAIL` | 网络是通的 | 同第 1 行 |
| `UP LINK_UP` 但 IP 是 `0.0.0.0` | 不通 | — | DHCP 没成功 | 重连：`wifi_test iwpriv sta stop` 再 conn |
| `LINK_DOWN` | 不通 | — | 链路标志没置上（本工程已修） | 见 [netdev 修复文档](aic8800d80_netdev_linkup_and_ping_fix.md) |

### 第 4 步：换一个出口做对照（最有效的一步）

如果不能确认是手机还是板子的问题，**换一台设备开热点**（另一部手机、平板，或家里的路由器），然后重做第 2 步：

```sh
wifi_test iwpriv sta conn <新热点SSID> <密码> 30000
# 等 dhcp finish
nettest 180.101.51.73 80
```

| 结果 | 结论 |
|---|---|
| 换热点后就 `CONNECT OK` | **原手机/运营商的问题**（多半是热点共享被限制），板子没问题 |
| 换热点后仍然 `TIMEOUT` | 回到第 5 步 |

### 第 5 步：需要找运营商/网管确认的内容

- 该套餐是否允许「个人热点 / 网络共享」；
- 是否对共享流量做了 TTL 检测并丢弃；
- 手机热点当前是否显示"无互联网连接"。

把这几条给出去即可，设备侧的排查已经做完了：

```
本机 MAC   : cc:c4:b2:dc:17:ed
本机 IP    : 10.237.107.34 / 255.255.255.0
网关 / DNS : 10.237.107.49
现象       : 可 ping 通网关、可解析公网域名, 但 TCP 与 ICMP 均无法到达任何公网地址
```

## 4. 现象速查表

| 现象 | 是不是故障 | 解释 |
|---|---|---|
| `ping: not found specified netif, using default netdev wl.` | **不是** | msh 的 `ping` 不传接口名，每次都走 `netdev_default`，所以每次都会打印 |
| `ifconfig: network interface device list error.` | **不是**（若在连接前敲） | netdev 是在 `sta conn` 流程里才注册的，连接前列表为空。要在 `dhcp finish` 之后敲 |
| `ping` 任何公网地址都 `timeout`，但网关正常 | **可能是真故障** | ⚠️ **不要当成"网络封 ICMP"就放过**。见下面「实战教训」 |
| 网关 ping 首个包必丢、第二个包耗时 100ms+ | **不是** | 空闲后需重建 BA 会话（日志里 `[FW] mm_ba_add_req_handler`），叠加 `g_sdio_irq_mask_forced=1` 的 10ms 轮询 |
| `ifconfig` 的 `FLAGS` 里没有 `ETHARP/BROADCAST/IGMP` | **不是** | 这三个位在本 SDK 里只被 `ifconfig` 的打印语句引用（`netdev.c:1137-1139`），纯显示项 |

### 实战教训（2026-10-12）

本工程真出现过"能 ping 通网关 + 能解析域名 + ping 任何公网地址全超时"的组合，
当时被推测为「运营商封 ICMP」/「手机热点禁止共享」——**两个推测都是错的**。
真实根因是 lwIP 的 `netif_default` 缺失（[补丁4](aic8800d80_lwip_netif_default_missing.md)），
属于**设备侧**问题。

原因：**netdev 版 `ping` 不打印 errno**，本地路由失败被它显示成和"对方没回包"一模一样的
`timeout`。所以：

> **`ping` 的 `timeout` 不能证明"包已经发出去了"。**
> 要区分"本地发不出去"和"网络丢包"，必须用 `nettest` 看 **errno + 耗时**：
> `0 ms` 一定是本地问题。

这个坑的代价是绕了两轮排查，故记于此。

## 5. `nettest` 实现说明（`src/main.c`）

三个关键点：

1. **为什么要单开线程**：lwIP 的 `connect()` 是阻塞的，且其内部 SYN 重传超时不可控（可能几十秒）。
   所以把 `connect()` 丢进一个工作线程，msh 侧用**信号量等待固定超时**，超时就打印 `TIMEOUT` 并返回。
2. **信号量不 detach**：超时返回时工作线程还阻塞在 `connect()` 里，若此时 `rt_sem_detach()`，
   线程稍后 `rt_sem_release()` 就会操作已销毁的对象。因此信号量只初始化一次、常驻，
   每次进入命令前先把上次残留的 token 抽干。
3. **域名支持**：入参先用 `inet_addr()` 试着按点分十进制解析，失败再走 `gethostbyname()`，
   所以域名用例顺带把 DNS 也验证了一遍。

工作线程栈 2048 字节、优先级 20；仅在手动执行命令时创建，跑完自动退出并由 idle 线程回收。
